# 本地变量工作台 · ESP32 验证版

双击桌面的「变量工作台」快捷方式，或运行本目录的 `VariableWorkbench.exe`。程序内置 Python 和串口依赖，使用系统 Microsoft Edge 打开独立应用窗口。请保留 EXE 旁的 `sample_esp32` 和 `state` 目录。

程序只监听本机 `127.0.0.1:8765`，首次启动默认关闭模型 API；已勾选记住的设置会自动恢复。扫描、生成面板和串口通信都可离线使用。关闭或刷新页面会释放串口；未勾选记住设置时还会清除内存 Key。窗口异常终止时，本地服务在 3 分钟无页面活动后退出并清除内存。服务的存活不依赖 Edge 启动进程。

可选模型设置支持 HTTPS 云端接口，以及 `http://127.0.0.1:端口/v1` 这类本机模型接口。启用云端接口后，点击「帮我选择」或「分析变量用途」才会把问题及候选摘要或相关源码片段发送给所填的服务商；Key 随认证请求发给该服务商，仅在用户勾选「在这台电脑记住设置」时，以 Windows 当前用户 DPAPI 加密写入 `state/model-settings.dpapi`。本地程序不能使云端 API 调用变成离线操作。

开发启动仍可使用 `start.ps1`，浏览器访问 http://127.0.0.1:8765 ，需要 Python 3 和 pyserial。

## 操作

1. 扫描预填的 `sample_esp32` 工程。查看可选表格、源码依据和同名变量隔离。
2. 勾选需要的字段，生成面板和 `main/generated_bridge.inc`。生成包含当前源码哈希的 schema 标识，输出 `state/manifest.json`。
3. 如果工作台已连接设备，先点「断开」释放串口。PowerShell 进入 `sample_esp32`，运行 `./build.ps1 -Flash -Port COM19`。这会替换此前的 USB 识别验证固件。
4. 工作台选择 COM19，连接并核对构建。查看温度曲线、修改模拟电机参数，观察确认与回读。

示例的 motor_t 是软件模拟，不输出 PWM、不控制任何物理电机。芯片温度使用 ESP-IDF 5.1.2 官方温度传感器 API，属于芯片内部温度，不能当作环境温度。范围超出驱动校准区间时会显示设备错误。

本地扫描不调用模型。可选 AI 有两种操作：「帮我选择」仅筛选已适配字段；「分析变量用途」读取本地提取的源码片段与调用关系并解释用途。点击「先看会发送什么」可在本地预览请求内容。Key 默认勾选本机加密保存，可取消勾选改为仅内存使用。界面不会读取并显示已保存的 Key。界面和 Python 服务都在本机运行。

## 首版能力边界

这是基于可扩展规则的验证版。支持全局 `motor_t`、约定的 motor_set_duty/motor_set_enabled 接口、调用 temperature_sensor_get_celsius 的公开包装函数。不会自动识别任意电机厂商的私有驱动。未确认的普通变量仅列为候选，不会生成可写控件。

首轮使用 CMake 显式 SRCS 预扫描，构建后使用 compile_commands.json。复杂 CMake/条件编译尚未做完整语义解析，显示候选必须由用户核对。当前绑定生成器要求工程已接入通用 bridge，示例包含该接入口。任意旧工程的自动补丁接入尚未实现。

每次生成会写入生成文件和面板配置。源码变化后，读取与写入都会被拦截并提示复核。设备 schema 不一致时禁止连接写入。通信使用 JSON 请求编号、设备确认和写后回读。其他改动如 SDK/编译器版本未被 schema 完整覆盖，schema 表示当前登记源码和字段绑定的一致性，不是完整 ELF 身份证明。

工程索引包含当前构建中/外的源码，以展示未参与构建的候选。忽略 build/.git/第三方托管组件/缓存。首版上限 5000 文件、单文件 2MB。数据曲线保留最近 180 次采样，尚未实现持久录制与离线回放。

## 用途分析（新）

本地提取普通 C/C++ 函数、标量/部分自定义类型声明、变量使用附近代码及调用链（最多两层包装函数），根据外围 API 调用优先提交相关候选，不按用户变量名称猜设备。外围 API 语义依据本机 ESP-IDF 5.1.2 头文件；例如 LEDC 是 PWM 输出线索，不能单凭它判断电机。

这是启发式源码索引，不是完整 AST 或数据流证明。暂不处理宏展开、复杂 C++、函数指针、通用跨文件全局引用和完整条件编译。作用域内的同一函数调用只表示可达关系，并不能证明每个变量都流入该调用；模型必须继续检查赋值及实参。当前最多索引 800 个变量，每项最多 18 段代码，每次分析最多提交 24 项、约 48 KB；界面显示截断与覆盖数，未提交变量不代表不存在。

模型每项结果必须引用已提交片段及原文，程序核对变量 ID、片段归属、引文及源码哈希。引文核对只证明原文存在，不证明推测正确。全部新用途判断仍为待确认，不获得串口写权限，不生成任意源码补丁；控制面板仍使用单独的已适配接口。

离线测试：`python -B -m unittest test_usage_analysis -v`。包含任意命名/两层包装、伪造引文、模型越权字段、离线预览及源码中途变化。测试模型响应为本地模拟，不代表已验证真实服务商。

## 分析反馈与诊断

用途分析按钮旁有加载动画与等待秒数，服务状态分为整理代码、等待模型及核对依据。结果、空结果、HTTP 错误、网络权限及超时都在分析区域内显示。界面等待上限 110 秒，服务网络超时为 80 秒（网络库的超时不是严格的请求总时限）。界面停止等待不会强制终止已发送的上游请求。

模型设置保存后清空输入框中的 Key 显示，不表示内存 Key 已删除。同一接口地址下，重新应用设置并留空 Key 会保留已有内存 Key；勾选记住设置后，重启会自动解密恢复；取消勾选后应用会删除加密文件并改为仅内存使用。点击「清除已保存设置」或关闭模型建议并应用，会同时清除内存与加密文件。加密文件绑定当前 Windows 账户，复制给其他账户不能直接使用；加密失败时不保存明文。接口错误只显示状态码和固定解释，不展示上游原始响应或凭据。`/api/analysis-status` 只返回当前阶段、等待时间及经过处理的应用错误。

针对明确变量名的问题会优先缩小提交范围，此处名称仅用于定位用户指定变量，不作为用途推断依据。界面模拟验证使用 `ui_fixture.py`，仅监听本机 8766/8767，不请求云端。`size_t used` 模拟延迟约 8 秒后返回 1 项结果，带 `fail` 的问题模拟 HTTP 401。模拟结果不代表用户真实 Key 的状态。

## 联网与蓝牙分析

在「让 AI 看懂变量的作用」中将分析范围选为「联网与蓝牙」。本地先列出调用证据，点击分析后由已配置的模型解释配置对象、连接状态、套接字句柄、收发缓冲区和长度等用途。覆盖 ESP-IDF Wi-Fi 配置/连接、IP 信息读取、MQTT 初始化/启动/发布/订阅、lwIP/POSIX socket/connect/send/recv/sendto/recvfrom，以及 Bluedroid BLE 扫描、GATT 客户端连接/写入等已核对 API。

支持常见的 Wi-Fi/IP 事件实例注册及 BLE GAP/GATT 客户端注册中直接传入的回调函数；从注册点链接到处理函数及其变量。动态函数指针、宏生成回调、NimBLE、任意第三方网络库尚未覆盖。POSIX 常见函数要求文件包含 lwip/sockets.h 或 sys/socket.h，项目自己定义的同名 send/connect 不直接算作网络证据。TCP/UDP 类型交由模型结合 SOCK_STREAM/SOCK_DGRAM 等实参核对，无法确认则保持未知。源码中有调用不代表运行时已连接，BLE 也不等于能上互联网。

发给模型的片段默认隐藏字符串/字符常量及注释内容，包括常见硬编码 SSID、密码和日志文字；数字常量、标识符及用户主动输入的问题仍保留，因此仍提供发送前预览。这是文本隐藏，不保证移除所有形式的秘密（如分散数字数组）。引文与提交的隐藏版片段核对，源码哈希与本机原文件核对。查看源码按钮读取本机原文件，不额外上传。

回归测试共 7 项，含不同命名、网络状态回调、Wi-Fi/MQTT/BLE/socket 线索、字符串与注释隐藏，以及防止把名为 wifi/mqtt 的普通变量或自定义 send 误当网络接口。

## 点选工程目录

点击路径框旁的「选择工程文件夹」，使用程序内的本地目录浏览窗口。支持桌面、文档、磁盘快捷入口、进入子文件夹及返回上级。包含 CMakeLists.txt 时可点击「使用这个工程」，路径自动回填，再点「查找工程里的设备」。取消不改变原路径；无工程入口的目录无法确认。目录只在本机浏览，不上传文件；单个目录最多显示 1000 个子文件夹。当前不是系统原生对话框，避免依赖缺失的 Tk 或无法稳定显示的系统选择窗口。

## STM32 工程分析

目录选择器现支持 STM32 CubeMX `.ioc`、CubeIDE `.project/.cproject`、Keil `.uvprojx`，以及带 STM32 标识的 CMake 工程。建议选择包含应用源码和工程配置的最外层工程目录，例如含 `.ioc`、`Core`、`MDK-ARM` 的目录。只选择 MDK-ARM 子目录可能看不到外部引用的 Core 源码。其他厂商 Keil 工程不会被误标成 STM32。

STM32 范围支持常见 HAL PWM/比较值、ADC、GPIO、UART（含 IT/DMA）、I2C、SPI 调用；补充了 F103 标准库 TIM_SetCompare1..4、GPIO_Set/Reset/WriteBit、ADC_GetConversionValue、USART_Send/ReceiveData 的用途线索。TypeDef 类型句柄可作为候选。不仅按变量名判断，模型仍需阅读相关赋值、实参和包装调用。

明确识别的 HAL/CMSIS、FreeRTOS 等底层库和标准库实现默认不展开；Drivers/BSP、Components 及自定义驱动保留，也不纳入当前应用源码哈希，避免大寄存器头文件及库内部变量挤占预算。未进行完整宏展开、链接或条件编译求值。compile_commands.json 可提供编译记录；缺少记录时 Keil 使用工程源码清单（多 Target 的合并结果），CubeMX/CubeIDE 仅预览源码，不能声称全部代码已参与实际构建。

STM32 当前支持本地代码分析、相关变量用途分析及源码溯源；没有 STM32 控制桥、自动修改、编译或烧录。界面隐藏 ESP32 专用控制步骤，服务端拒绝给 STM32 生成 ESP32 控制绑定。切换工程会释放旧串口并清除当前控制面板，避免操作上一个工程的设备。

只读实测：桌面 F103 标准库工程（STM32F103C8）与 U575 HAL 工程（STM32U575RITx）均能扫描；原始工程未写入。回归命令 `python -B -m unittest test_usage_analysis -v`，当前 10 项。

## 电机与设备清单

新增「工程里的电机与设备」。本地先按接口句柄、PWM 通道和 I2C 地址表达式分组，初始只称为接口线索；同一串口发送函数不会各自变成一个设备，PWM 通道也不会直接认定为电机。点击「AI 识别设备」后，模型结合驱动实现、直接包含的工程头文件、枚举、角度映射、数据帧编码/解码及读写入口，整理设备类型、独立实例和功能。

每个模型实例必须引用已提交的接口 ID，并在原文引文中给出真实存在的实例标识。未知接口、重复实例、虚构代码或实例标识会被拒绝；引文存在不等于设备身份已经证明，全部结果仍是待确认。允许同一 UART 链路下列出有协议/枚举证据的多个逻辑设备。

清单支持分别勾选关注设备、修改显示名称、展开功能与源码依据。此处是本次会话的关注项，不会发送控制指令，也尚不生成 STM32 实时控制组件。底层 HAL 调用表收进高级详情。

每次设备识别按模块提交，最多 128 项本地接口线索，每个源文件/关联头文件最多 400 行、每个片段 60 行，输入约 60 KB；截断或跳过模块时标注部分覆盖。只显示被本地接口规则捕获的上下文，其他协议、纯软件 I/O、动态拓扑可能遗漏，不能据此宣称已经找全设备。

回归测试共 12 项，包括接口/通道合并、独立设备标识引用、拒绝虚构接口以及禁止模型赋予实时写权限。

## 常见模块分类

新增本地常见模块线索库，类别、型号和驱动状态分开显示。初始条目包括 MPU6050、ISM330DHCX、BMI270、BMI088、ICM-42688、VL53L0X、VL53L1X、TF-Luna 与 TFmini 系列，来源见 common_modules.py 中的官方资料或原始驱动文档链接。此清单可扩展，并不保证识别所有常见模块。

分类依据包括代码中的驱动标识及实际接口/模块调用；注释和日志字符串不参与匹配。共享协议帧只建议系列类别，不硬判具体型号。ISM_CS 与 ISM_INT 的组合仅给出低置信度「疑似 IMU」接口线索，ISM 短前缀有歧义，不能据此确定 ISM330DHCX、轴数或采样功能。常见 I2C 地址单独出现不用于确认型号。

设备包额外携带本地线索及来源，并最多补充两份用户调用文件的上下文，避免通用总线包装函数遮住上层传感器的寄存器访问和数据处理。设备引用继续检查接口与源码哈希。启动时不再恢复或自动扫描外部工程，用户主动选择并点击扫描后才读取。当前工程路径和已验证的设备结果保存在 state/project-session.json，API 地址/模型/Key 不写入这个文件。

当前回归测试 18 项。部分代码匹配只说明程序意图，不证明实际硬件连接或驱动可以运行；界面分别显示「驱动标识匹配」「疑似接口」和是否发现读取相关代码。

## 引用校验修复与测试工程边界

多行代码引用现在按代码 token 对比，忽略展示行号及排版；不同的标识符、通道、运算符仍会被拒绝。设备结果逐项核验，合格项保留，不合格项列出名称、序号、对应片段及失败原因。全部失败时保留本地接口线索并明确显示未得到可核验结果，不把整个失败请求显示为成功识别。

启动仅扫描内置 sample_esp32，不自动恢复或读取上次的外部工程。开发验证只使用本目录的样例及自建临时测试，不自行使用用户 D 盘其他工程作为用例，不自行把这些工程提交给模型。用户手动选工程、点击扫描/识别仍可正常测试。原有 project-session.json 只是本地记录，不在启动时采用其中的测试工程路径。

回归测试 21 项；本地接口模拟验证通过：正确的多行引文保留 1 项、故意伪造引文拒绝 1 项。ui_fixture.py --devices 使用本目录自建样例，隔离的 state/ui-fixture-state，不访问用户测试工程，也不调用云端模型。

## 编码器、OLED 与分类串位修复

新增 HAL_TIM_Encoder_Init/Start/Start_IT/Start_DMA、计数读取与设置的接口线索。同一文件、同一定时器的编码器计数读写归入其编码器接口；未见编码器模式的普通计数器保持 COUNTER。接口 ID 改为固定短 ep_ 标识，减少长路径、空格、换行引起的模型复制错误。

设备包先为各接口分配实际调用片段，再补头文件和其余上下文，约 60 KB 上限不变；明确的字库/图片大数据头文件不参与设备识别。GPIO 初始化掩码可以关联相同端口、已证明为其子集的 GPIO 引脚驱动代码，不能引用其他端口的任意代码。

GPIOA_PIN_2 这类显示组合名只有在同一条已核验 GPIO 调用能证明 GPIOA 与 GPIO_PIN_2 时才接受，其他虚构组合仍拒绝。PWM/编码器不会因为 main.c 包含 MPU6050.h 而被装饰成 IMU；ISM 弱线索只绑定真正的片选端口/引脚，不能污染同文件其他 GPIO。明确的传感器模块与模型类型冲突时统一标题、标注原始模型名称并暂停采用冲突功能说明。

当前回归测试 27 项，新增用例均为工作台目录下自建内容。未用用户其他 D 盘工程重跑或向模型提交；启动仍只打开内置示例，私人工程由用户自行导入验证。


## Halpractice 实测与引用修复

`check_halpractice_api.py` 通过本地服务测试 3 份已授权工程，使用程序中已有的设置，不读取或打印 Key。`--source` 用独立 Python 进程加载已加密设置，方便验证源码修复；原工程只读，报告写到本程序的 `state` 目录。

设备证据跟进至多 3 层无歧义项目头文件。枚举常量只有在驱动数组索引或 switch 分支中实际使用时，才加入实例提示，不按常量名称判定电机。模型简称、错误片段编号或接口编号，仅在原代码能够逐项证明时规范化；修复记录可在「为什么这样判断？」中查看。无法匹配的结果继续跳过。

实例引用可由同一接口的完整调用补充绑定；GPIO 别名必须同时匹配端口与引脚定义。引用链接定位到实际引文行，不再只跳到 60 行片段的开头。以上校验只证明代码存在和引用关系，不保证模型用途判断正确，也不授予实时控制权限。

AI 未返回可核验实例时，本地常见模块线索仍可补充显示，但会明确标为实例未确认，并与 AI 候选分别计数。Halpractice 实测明细见 `HALPRACTICE_CHECK.md`。


## STM32 / ESP32 通用串口收发

第 3 步现在独立显示串口连接区，不依赖工程类型或是否生成面板。选择「普通串口收发」、COM 口和与固件一致的波特率（默认 115200），打开串口即可接收日志，或手动发送 UTF-8 文本、十六进制字节。支持 LF/CRLF 文本结束符、文本/HEX 接收显示、收发计数和清空记录。数据格式固定 8N1，接收记录最多保留 64 KB 原始数据 / 200 项，界面滚动显示。

普通连接不发送任何握手，不需要 API Key，也不会因选中设备而自动发送控制命令。打开 COM 口仅表示电脑侧连接成功，不能据此认定传感器在线。STM32 板需通过 USB 转串口、支持 VCP 的调试器，或固件启用的 USB CDC 向电脑暴露串口；只有烧录/调试功能的接口不一定提供 COM 口。

ESP32 已适配示例继续使用「已适配的控制面板协议」，发送 hello、核对 schema 后才启用字段读写。普通串口模式下字段写入和面板轮询均不启用。STM32 目前新增的是通用串口收发；把 AI 识别出的变量连接到实时图表/电机控制仍需要固件侧协议适配，不能通过隐藏限制来冒充已完成。

软件验证：`python -B -m unittest test_serial_console test_usage_analysis test_api_settings -q`。串口新增测试使用 pyserial 软件回环，不代表完成了 STM32 实物连接测试。


## PID 控制环调参方案

工程扫描新增控制环清单。首版通过结构体 Kp/Ki/Kd（大小写均可）及增益乘法计算识别控制器候选；实例名称不决定用途。可点击「AI 解释控制环」，仅提交控制计算、调用实参和附近反馈量构造片段，结合积分、目标与反馈判断位置/速度/姿态/转向等环类型。结果为引文已核对的建议，允许手动修改名称与类型。

同一函数中，前级计算结果直接作为后级实参时显示串级候选；叠加进表达式时显示混合依赖候选。已发现的中间赋值会阻断旧依赖。条件分支、完整路径可达性、跨函数及宏数据流尚不证明，不能把该图当作已验证控制框图。

展开每个环可填写 Kp、Ki、Kd；有多个赋值位置时必须选择来源，不把最后一条文本赋值当作运行时最终值。无显式数值来源的参数可仅保存到方案，不能生成绑定源码补丁。保存前校验所有扫描文件哈希。方案和统一差异补丁写到 `state/pid-<工程哈希>.json/.patch`，原工程和开发板均不变；重新打开相同工程可恢复方案。

当前工作台尚未适配 STM32 PID 在线协议，因此界面不会发送猜测的调参命令，也不把本机方案标记为设备生效。实时调参需进一步接入固件的字段读写、范围校验、确认与回读。数组 PID、宏定义系数、独立散变量和复杂 C++ 还未匹配。本功能与 API Key 加密保存、普通串口功能可独立使用。

实测 `qianrushidasaitest_1`：4 个结构体控制器；位置输出叠加到角度计算，角度输出再进入角速度计算，转向单独输出。真实模型在补充反馈积分上下文后将 `speed_vel` 识别为位置环候选；其余为角度、角速度、转向候选。源码中的命名和控制公式仍需用户核对，未做实物调参。

补充核对：`qianrushidasaitest_1/myself/ai_debug.c` 已有旧 CSV 调参代码，涵盖角度/角速度的部分 P、D 和零点；但 `Core/Src/main.c:105` 的 `ai_debug_init()` 被注释，不能视为当前固件已经启用。它也不等同于所有控制环的通用 Kp/Ki/Kd 协议。此次未修改或启用原工程中的该接口。


## qiansaitest 条件编译漏识别修复

`#if/#else` 中互斥分支的成对开括号会干扰直接大括号计数。现对这类函数保留到下一个明确函数定义的词法范围，调用标记为条件编译范围，不断言活动分支。未定位调用的实例保留共享类型计算证据，AI 不得据此确认实例用途。

PID 请求加入压缩后的调用上下文，并沿输入变量在同一源文件内的直接函数赋值补充生产函数代码；这帮助区分 GPIO 加权循迹偏差与陀螺仪角速度。模型结果被跳过时返回逐项原因，不再把“0 条通过核验”显示为成功理解。切换工程时清除过期提示。

设备模型追加无效引文时，若还有属于所选接口的精确代码引文，会剔除无效引文、重新执行全部实例绑定校验；仅在实例校验仍通过时保留候选，并清空原功能断言、明确标注部分引文和待复核功能。只有无效引文或实例虚构时仍拒绝。

当前工程实测：4 个 PID 候选，左/右轮速度环及循迹偏差环有调用证据；angle_vel 未定位直接调用，类型保持待确认。设备真实响应回放保留左右电机、左右编码器、步进电机、视觉模块和 OLED 候选，其中部分为仅保留有效引文的待复核项。66 项软件回归检查通过；原工程只读。

## 深色记录分析工作台

新版使用深石板色背景和柔和青绿色强调色，表单、展开卡片、选中行和聚焦状态保持清晰对比。左侧新增「记录与分析」；该页面和串口页独立于工程扫描，顶部工程框在这两页收起。

无设备体验：进入「记录与分析」，选择已有的 [模拟] 400 样本记录，或点击「生成模拟记录」；选择 angle_deg / encoder_count 后点击分析。模拟样本按 20 Hz 生成，含角度阶跃、编码器 4096 周期回绕和人为突变，以及一个 0.5 秒附加时间间隔。模拟参数预设：角度单步阈值 10 度、编码器单步阈值 100 计数；可以在分析设置中修改。全程不调用模型、不需要 API Key，不能据此证明真实设备性能。

真实采集：在普通串口模式连接设备后，进入记录页点「开始串口记录」，停止后仍可回放。记录期间有独立后台读取，不依赖曲线页是否打开。支持换行分帧 JSON、key=value、带表头 CSV；JSON/键值中的 t 按秒处理，未提供时使用本机收到每行的时刻（USB 批量到达可能影响速率与间隔分析）。二进制暂不解码为数值，但原始收发 HEX 和文本记录保存在 raw.jsonl。未完成的末帧不拼造为样本。

每条记录保存到 state/records/<ID>/，含 meta.json、samples.jsonl、原始串口数据 raw.jsonl（真实串口时）、导出的 samples.csv 和每通道 analysis-*.json。模拟/实采来源同时标注于界面、元数据和 CSV source 列。最近 100 条记录可在界面选择；更早文件仍保留。每条最多 10 万数值样本、12 通道，原始数据约 50 MB。异常退出的活动记录会标记未正常结束，已经写入的数据继续保留。

本地分析包含曲线、均值、范围、标准差（含正常运动）、净变化、变化率、采样间隔异常候选、非递增时间戳、回绕校正与突变候选。编码器每圈计数必须人工确认；角度类型需选择度或弧度。回绕校正假设每步变化小于半周期。参考通道必须同单位；角度指定回绕周期后偏差采用周期内最短差。自动突变阈值结合单步变化中位数/MAD及高分位，正常快速运动也可能触发，可手动配置，不能直接判定故障。

验证：74 项软件检查通过（另 1 项 Windows 加密检查按需独立运行）；包括逐行断帧重组、原始收发保存、模拟/实采标记、CSV 导出、HTTP 报告落盘和回绕/突变/间隔统计。软件串口回环不代表真实 STM32 采集已验证。

## 本地 PID 运行诊断（2026-11-08）

在「记录与分析」下方使用「运行诊断与试调」。点「生成 4 组 PID 模拟数据」得到持续震荡、改善曲线、微分噪声、饱和积分四组本地记录，每组 600 样本，50 Hz。它们是人工构造的测试信号，参数标签并非被控对象模型推导结果，不能证明调整 PID 导致曲线改善。

实际角度与目标角度为必填信号；角速度、输出、I 项和 D 项可选。I/D 必须是与控制输出同单位的各项贡献。可查看后段 RMS、震荡频率、幅度趋势、饱和占比、积分变化和微分项与输出相关性。三幅图共用时间轴，可播放、暂停、拖动光标。当前角度诊断需要连续角度；超过半圈的单步跳变会阻止数值试调。

诊断给出数据依据、可能原因、排查项与条件化方向，不能唯一识别 PID 根因。仅当持续震荡、未明显饱和、无明显微分噪声、已确认参数/反馈且控制周期与数据间隔吻合时，生成单独将 Kp 降低 5% 的待验证试验值。这是启发式试验步长，不是自动整定或硬件安全保证。其他情况只给排查方向。

诊断报告保存至 state/records/<ID>/diagnoses/，带数据 SHA256、信号映射、运行参数声明、源码扫描快照。实采开始时冻结用户声明的参数，明确区别于设备回读。对比报告保存在 records/comparisons/，保留前后参数快照；工况、单位、时间或限幅不一致时提示不可直接比较。对照模拟数据的改善百分比仅为两条人工曲线的统计差异。

关联当前工程的控制环后，可将报告中的试验值加入本机 PID 方案。保留已有其他参数，默认不选择源码赋值位置，不发送串口命令；仍需用户核对来源、预览补丁并自行编译烧录。记录或源码变化会阻止采用旧报告。模拟报告始终标记模拟来源。此流程不调用模型、不需要 API Key。

IMU963RA 模块的本地线索现在分别显示 LSM6DSR 的加速度/陀螺仪与 QMC5883L 磁力计。寄存器定义与读取入口分开标注；仅有定义不会显示成磁力计已采样，硬件状态仍需实测。

## 模拟屏幕与分区提问
